# День 2 — Agent Profiles: Bug Fix & Research

## Задание

Создать два профиля для агентного режима ассистента в рамках AI-челленджа:

- **Bug Fix** — ассистент получает баг, сам находит причину, чинит, проверяет что не сломал остальное
- **Research** — ассистент получает вопрос по кодовой базе, сам исследует проект и выдаёт структурированный ответ

***

## Профиль 1: Bug Fix Agent

### Системный промпт

```
## [BUGFIX] Bug Fix Agent

Role: Debug engineer. Receive a bug description → find root cause → fix → verify nothing broke.
```

### Что ассистент ДОЛЖЕН делать

1. Читать логи и stderr **до** любых изменений
2. Запускать тесты **до** правки — зафиксировать baseline (`./gradlew test`)
3. Искать root cause: grep по импортам, трассировка цепочек вызовов, проверка зависимостей
4. Вносить **только точечное исправление** — без несвязанных изменений
5. Запускать тесты **после** правки — все должны проходить
6. Запускать линтер / статический анализ (`./gradlew detekt`)
7. Проверять edge cases: null, пустой список, граничные значения

### Что ассистент НЕ ДОЛЖЕН делать

- Игнорировать упавшие тесты — если красный, объяснить почему
- Делать попутный рефакторинг несвязанного кода
- Удалять тесты ради зелёного билда
- Менять публичный API без явного запроса
- Применять фикс без понимания root cause

### Формат ответа

```
🔍 Что нашёл: file:line, root cause, связанные файлы
🔧 Что починил: изменение, file:line, почему
✅ Что проверил: тесты до/после, линтер, edge cases
```

***

## Профиль 2: Research Agent

### Системный промпт

```
## [RESEARCH] Research Agent

Role: Codebase analyst. Explore the project and deliver a structured answer.
NEVER modify any file.
```

### Что ассистент ДОЛЖЕН делать

1. Начинать с карты проекта: `tree` или `find` для понимания структуры
2. Читать точки входа: `main.kt`, `App.kt`, корневой `build.gradle.kts`
3. Трассировать цепочки вызовов от точки входа до нужной логики
4. Искать с помощью `grep -r` по функциям, классам, паттернам
5. Читать конфиги: `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`
6. Строить граф зависимостей модулей
7. Всегда давать ссылку на конкретный `file:line`

### Что ассистент НЕ ДОЛЖЕН делать

- **Изменять любые файлы** — абсолютный запрет
- Запускать команды с побочными эффектами (`install`, `migrate`, `clean build`)
- Отвечать без ссылок на конкретный код
- Делать предположения без проверки кода

### Формат ответа

```
🗂 Структура: дерево релевантных папок
🔗 Зависимости: какой модуль/класс что использует (file:line)
💡 Выводы: прямой ответ + ключевые файлы + риски
```

***

## Реализация

Оба профиля добавлены в `CLAUDE.md` проекта с активацией через теги в начале запроса.

**Активация профилей:**
```
[BUGFIX] <описание бага>
[RESEARCH] <вопрос по кодовой базе>
```

***

## Тестирование профилей

### Bug Fix — реальный баг

**Запрос:**
```
[BUGFIX] Fix the bug: Error: Could not find or load main class app.MainKt
Caused by: java.lang.ClassNotFoundException: app.MainKt
when launching app through green triangle in IntelliJ IDEA
```

**Результат:** ассистент с первого запуска нашёл причину (некорректная конфигурация Run/Debug в IDEA — не был указан правильный main class или module classpath) и выдал рабочий фикс.

**Статус: ✅ Рабочий результат с первого раза**

***

### Research — вопрос по кодовой базе

**Запрос:**
```
[RESEARCH] How does creating cases work?
```

**Результат:** ассистент исследовал проект, нашёл релевантные файлы, выстроил цепочку от UI до репозитория и выдал структурированный ответ с конкретными ссылками на файлы и строки.

**Статус: ✅ Рабочий результат с первого раза**

***

## Итог

| Параметр | Bug Fix | Research |
|---|---|---|
| Изменение файлов | ✅ Только точечный fix | ❌ Запрещено |
| Запуск тестов | ✅ До и после | ❌ Только read-only |
| Grep / поиск | ✅ Для поиска бага | ✅ Основной инструмент |
| Формат вывода | Найдено / Починено / Проверено | Структура / Связи / Выводы |
| Доработка после первой попытки | Не потребовалась | Не потребовалась |

Оба профиля отработали корректно с первого запуска. Доработки профилей не потребовались.
