# 🔥 День 3. Testing: QA Scenario Manager

В рамках третьего дня челленджа была реализована полностью автономная система тестирования (Agentic QA Workflow) для десктопного Kotlin-приложения (Compose Multiplatform).

Система объединяет два уровня проверок и работает проактивно при добавлении новых фичей.

## 🎯 Что было сделано

### Уровень 1. Автотесты на код (Unit/Integration)
- Настроено автономное покрытие бизнес-логики (`ViewModels`, `StateFlow`) с помощью JUnit 5 и Coroutines.
- Агент самостоятельно пишет тесты, запускает `./gradlew test`, анализирует ошибки компиляции/выполнения и доводит билд до "зеленого" состояния.
- Реализован пайплайн в виде bash-скрипта (`qa-pipeline.sh`) для интеграции проверок в CI/CD (например, перед PR).

### Уровень 2. Smoke-сценарии через UI (MCP)
- Агент автономно собирает и запускает Compose Desktop приложение локально (`./gradlew run`).
- С помощью **MCP** (десктопная автоматизация) агент визуально "прокликивает" интерфейс, не опираясь на внутреннее дерево элементов (которое скрыто Skiko-движком).
- Агент сверяет состояния кнопок, навигацию, поиск, фильтры и делает скриншоты каждого шага.
- После успешного или неудачного прохождения всех шагов приложение корректно закрывается агентом.

### 🌟 Усиление: Feature Development Lifecycle (Интеграция в Flow)
Вместо ручного вызова тестов, мы "научили" агента проактивности, зашив правила работы в файл `CLAUDE.md`.
Теперь при просьбе реализовать новую фичу (проверено на добавлении **Dark Theme Toggle**), агент выполняет строгий SOP (Standard Operating Procedure):
1. Пишет код фичи.
2. Обновляет/пишет юнит-тесты и добивается их прохождения.
3. Добавляет новые шаги в чек-лист UI-сценариев.
4. Запускает приложение и тестирует новую кнопку/логику мышью через MCP (сохраняя скриншоты).
5. Формирует единый `final-qa-report.md`.

## 📂 Результаты (Артефакты)
- `CLAUDE.md` — обновленные инструкции с профилем агента `[FEATURE]`.
- [ui-smoke-report.md](./ui-smoke-report.md) — первый базовый прогон UI-тестов по навигации и поиску (5/5 успешных шагов).
- [final-qa-report.md](./final-qa-report.md) — финальный объединенный отчет после добавления фичи Dark Theme (успешное прохождение Unit-тестов и 8 UI-шагов переключения темы).

## 🚀 Как запустить проверку
1. Создать/изменить фичу через промпт для Claude Code:
   > "Implement a [Feature Name] on the Dashboard screen. Please follow the Feature Development Lifecycle rules defined in CLAUDE.md."
2. Агент сделает всё остальное.
